## 6. "Olvidé mi contraseña" por Email (NO implementado aún)

### Diseño propuesto

**Tabla: `password_reset_tokens`**
```sql
CREATE TABLE password_reset_tokens (
    id              bigint GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    usuario_id      integer NOT NULL REFERENCES usuarios(id) ON DELETE CASCADE,
    token_hash      varchar(128) NOT NULL,  -- hash del token (bcrypt/argon2), NO guardar token plano
    expira_en       timestamptz NOT NULL,   -- ahora + 30 minutos
    usado_en        timestamptz,            -- NULL = no usado; timestamp = ya usado
    creado_en       timestamptz NOT NULL DEFAULT now()
);

CREATE INDEX idx_password_reset_tokens_usuario ON password_reset_tokens (usuario_id);
CREATE INDEX idx_password_reset_tokens_expira ON password_reset_tokens (expira_en) WHERE usado_en IS NULL;
```

**Flujo:**
1. Usuario ingresa email en `/login?mode=forgot` (pública)
2. Backend busca usuario por email (case-insensitive)
3. **SIEMPRE responde 200 OK con mensaje genérico** ("Si el email existe, recibirás instrucciones") — **no revelar si el email existe**
4. Si existe: genera token aleatorio (32 bytes), guarda `bcrypt(token, 12)` en BD con `expira_en = now() + 30 min`
5. Envía email con link: `/resetear-clave?token=TOKEN_PLANO&email=EMAIL`
6. Usuario hace click → página `/resetear-clave` valida token:
   - Busca por email → compara `bcrypt(token_plano, token_hash)`
   - Verifica `expira_en > now()` y `usado_en IS NULL`
   - Si OK: muestra formulario para nueva contraseña (política: 12 chars, no comunes)
   - Al enviar: actualiza `password_hash`, setea `usado_en = now()`, `debe_cambiar_password = false`, `token_version++`
   - Invalida todos los tokens del usuario (UPDATE ... SET usado_en = now() WHERE usuario_id = $1 AND usado_en IS NULL)
7. Rate limit: máximo 3 requests por email/hora, 10 por IP/hora (tabla `rate_limit` existente)

**Requisitos previos:**
- SMTP configurado en `configuracion_notificaciones` (ya existe tabla)
- Variables de entorno: `SMTP_HOST`, `SMTP_USER`, `SMTP_PASS`, `EMAIL_FROM`
- Job/queue para envío asíncrono (evitar bloquear request HTTP)

**Endpoints a crear:**
- `POST /api/auth/forgot-password` — recibe email, inicia flujo
- `GET /resetear-clave?token=...&email=...` — página para ingresar nueva clave
- `POST /api/auth/reset-password` — valida token y actualiza clave

**Seguridad:**
- Tokens de un solo uso (marcados `usado_en`)
- Expiración 30 min
- Respuesta idéntica exista o no el email (prevención de user enumeration)
- Rate limiting en endpoint de solicitud
- Logs de auditoría en `auditoria_cambios` (acción `PASSWORD_RESET_REQUEST`, `PASSWORD_RESET_COMPLETE`)
